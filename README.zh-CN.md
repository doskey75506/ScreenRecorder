# ScreenRecorder

[![CI](https://github.com/doskey75506/ScreenRecorder/actions/workflows/ci.yml/badge.svg)](https://github.com/doskey75506/ScreenRecorder/actions/workflows/ci.yml)

[English](README.md) | 简体中文

独立运行的原生 macOS 录屏、视频编辑、转码与压缩程序。使用 SwiftUI / ScreenCaptureKit 录制、AVFoundation 预览、FFmpeg 处理视频；不需要 Python 或浏览器服务。

## 主要功能

- 录制显示器或应用窗口，可选来源音频和麦克风。
- 在显示器上拖出矩形，只录制框内的屏幕区域。
- 裁剪画面、截取时间段，将多个视频片段按顺序拼接。
- 支持 H.264、HEVC、VP9、AV1，以及 MP4、MOV、MKV、WebM 容器，具体组合见下表。
- 提供原始分辨率、1080p、640 档和三档画质，实时估算导出大小。
- 编辑时保留独立临时副本，导出另存新文件，保护原视频。
- 支持 English / 简体中文界面，首次启动默认英文，可在窗口右上角即时切换并记住选择。

## 构建与启动

需要 **macOS 15+、Xcode 16.4+**。视频编辑、转码及更多录制格式还需要本机安装 **FFmpeg（包含 ffprobe）**：

```sh
brew install ffmpeg
```

程序自动查找 `/opt/homebrew/bin`、`/usr/local/bin` 和应用包 `Contents/Resources/Tools` 中的工具，只展示工具实际具备的编码器。当前构建不捆绑 Homebrew 的二进制或动态库；复制 `.app` 到另一台 Mac 后，需要在那台机器安装匹配架构的 FFmpeg。原生 H.264 MP4 录制本身不依赖 FFmpeg。

获取源码并构建：

```sh
git clone https://github.com/doskey75506/ScreenRecorder.git
cd ScreenRecorder
./scripts/build.sh
open build/DerivedData/Build/Products/Release/ScreenRecorder.app
```

也可以打开 `ScreenRecorder.xcodeproj`，选择 `ScreenRecorder` scheme 后运行。构建脚本生成同时包含 Intel `x86_64` 和 Apple Silicon `arm64` 的 `.app`，使用本地临时签名，不需要开发者账号。当前版本未公证，适用于本机开发与使用。

请从 `.app` 或 Xcode 启动，以便 macOS 正确识别录屏和麦克风权限；`swift run` 仅适合代码开发，不作为正式启动方式。关闭主窗口后程序仍在菜单栏运行，可从菜单栏重新打开窗口、停止录制或退出。

## 使用

窗口右上角的语言菜单可切换 **English / 简体中文**，无需重启。切换不会清空当前项目、裁剪或片段列表。系统选源器、文件对话框及系统错误信息仍由 macOS 的语言设置决定。

1. 从预览上方并列的 **“区域 / 屏幕 / 窗口”** 开始。屏幕和窗口打开可搜索的应用内列表，由 ScreenCaptureKit 实际请求访问；也可改用系统选源器。区域会立即进入桌面拖框。
2. 设置编码、容器、分辨率和保存目录。默认 **H.264 MP4、30 fps、原始分辨率、SDR**；分辨率还包括 1080p 和 **640×480 范围内等比例缩放**（16:9 视频输出 640×360），均不放大小视频。
3. 按需开启来源音频和麦克风；麦克风可选择输入设备。首次使用时按系统提示授权。
4. 开始录制，完成后点击“停止并保存”，也可使用菜单栏停止入口。
5. 自动进入编辑页。拖动裁剪框四角、移动选框，或输入各边裁去的像素；设置开始和结束秒数，预览选中片段后导出。

“视频编辑 / 转码 / 压缩”中的“导入视频…”可以读取磁盘视频，复用与录屏相同的裁边、时间截取、分辨率和画质设置。无需裁剪时，保持完整画面和时长即可直接转码或压缩。MKV / WebM 等不支持原生播放的格式使用静帧预览，调整起止时间可查看对应画面，仍可编辑与转码。

### 减少重复的 Share 确认

在 **系统设置 → 隐私与安全性 → 屏幕与系统音频录制**（部分版本称“屏幕录制”）中允许实际运行的 ScreenRecorder，并按 macOS 提示重启。之后点击“屏幕”或“窗口”会显示应用内来源列表，不再每次主动打开系统 Share 选源器；区域录制也会在框选后复用此权限。

列表支持搜索和刷新。明确选中来源后，点击 **“预览所选来源”**，再使用独立的 **“开始录制”** 按钮。程序不会自动选中第一项。刷新时若窗口消失会清空选择，确认时再次核对来源，取消则保留原来的预览。也可随时从列表点击 **“使用系统选源器…”**。

载入和确认来源时会重新检查权限。未获权限时仍可使用系统选源器。macOS 自己的权限提示由系统控制；本功能减少的是程序主动发起的重复 Share 流程，不会自动修改系统隐私设置。

### 权限已开启但仍无法捕获

临时签名会随每次构建改变。macOS 可能保留旧签名的已开启条目，却拒绝更新后的应用。请退出所有 ScreenRecorder 副本，在 **“屏幕与系统音频录制”** 中移除旧条目，用 **+** 重新添加已安装的 `.app`，再打开应用。日常固定使用一个安装副本。捕获失败会显示错误域和错误码；真正的权限拒绝还会显示当前应用路径和构建号，其他错误不再一律提示检查权限。

如需更新后保持权限，请持续使用同一个 Apple 签发的签名证书。钥匙串已有证书时，使用准确的身份名称构建：

```sh
SCREENRECORDER_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" ./scripts/build.sh
```

构建不会创建证书或修改隐私设置。没有证书时，本地及 CI 继续使用临时签名，更新后可能需要重新授权。参见 [Apple 对此签名问题的说明](https://developer.apple.com/forums/thread/819406)。选源现在由 ScreenCaptureKit 实际结果决定，不再仅因 CoreGraphics 预检查失败就强制进入系统 Share 流程。

### 区域录屏

点击 **“区域”** 后，主窗口立即隐藏，桌面出现拖框遮罩。在所需显示器上拖出矩形，松开鼠标确认；按 **Esc** 或右键可取消。拖框本身无需先完成录屏授权。区域模式直接向 ScreenCaptureKit 请求访问。若被系统拒绝，会停止并显示修复说明，不会接着自动弹出另一轮 Share。macOS 15.2 及更新版本也可先通过“屏幕 → 使用系统选源器”共享屏幕，再在同一屏幕上框选。窗口中的 **“取消选择”** 可随时返回起点，避免选源未完成时控件一直锁定。

预览和录制都直接捕获框内画面，预览上方显示实际像素尺寸。分辨率设置以该区域为基础等比例缩放；过小区域不能确认，尺寸向内对齐到整数偶数像素。取消时保留原来的来源和区域。选择 **“屏幕”** 可录制整屏，重新选择 **“区域”** 可重画。录制期间禁止更改来源。

三个来源入口固定在预览上方。保存目录和 **“开始录制 / 停止并保存”** 固定在右侧底栏，设置内容单独滚动，选项变长也不会把关键按钮挤出窗口。

macOS 15.0–15.1 使用此模式需要系统设置中的屏幕录制权限，授权后 macOS 可能要求重启应用；可直接在所需显示器上框选。框选只限制**画面**，来源音频仍按显示器捕获，不会按矩形隔离声音。

### 分段拼接

1. 点击“导入视频…”一次选择一个或多个原始视频，在“原始视频”菜单中切换来源。
2. 选择该视频的起止时间、设置裁边，点击“加入拼接列表”。可以从同一视频反复选取不连续的片段，也可以添加不同视频的片段。
3. 列表从上到下就是最终顺序。使用上下箭头调整顺序、减号移除片段；点击某段可恢复它的裁边和时间，修改后点击“更新所选片段”。
4. 点击“导出拼接视频…”，只合成列表中的片段。当前尚未加入或更新的时间选择不会自动写入列表。文件大小估算按所有片段的合计时长更新。

输出画布由列表第一段的裁后尺寸和输出分辨率设置决定。其他片段保持比例缩放，必要时补黑边；帧率和音频采样率统一处理。有声音和无声音的视频混用时，无声音的片段补静音，避免后面的声音错位。

列表为空时，仍可直接导出当前视频的一个时间段；“清空列表”返回该模式。“新建项目”清空本次来源与片段列表，原视频及已经导出的文件保持完整。项目列表暂不跨应用重启保存。

### 连续编辑与源文件保护

载入视频时会保留本次编辑专用的独立临时副本，预览与每次导出都使用这份副本，不会自动改用上一次的导出结果。可以继续修改时间并再次导出，无需重新打开文件；即使外部原文件被移动、删除或原地修改，也不会影响已经载入的片段。

APFS 上优先采用共享存储的克隆副本；其他磁盘可能需要复制文件并占用额外空间。新建项目、释放编辑会话或正常退出程序时清理临时副本。已经在旧版中丢失的源文件需要重新选择现存的视频，新版不能恢复已经删除的内容。

导出另存为新文件，原视频保持完整；重名时增加数字后缀。支持取消导出并清理未完成的临时文件。录制失败时已有文件会保留，但中断文件不保证可播放。

默认录制位置为 `~/Movies/ScreenRecorder/`，目录选择会被记住。录制来源窗口改变尺寸时，输出画布仍保持开始录制时的尺寸。

## 格式、画质与文件大小

| 视频编码 | 容器 |
| --- | --- |
| H.264 | MP4 / MOV / MKV |
| HEVC / H.265 | MP4 / MOV / MKV |
| VP9 | WebM / MKV |
| AV1 | MP4 / WebM / MKV |

WebM 使用 Opus 音频，其余使用 AAC。AV1 编码通常较慢。系统录屏接口无法直接输出的组合，会先保存 `*-source.mp4`，停止后自动复用转码流程生成所选格式；失败或取消时原始录屏仍保留。

导出画质提供 **高画质 / 均衡（默认） / 小文件** 三档。菜单会根据选定画面的输出尺寸、编码、时长、来源码率和音频预算，显示各档预计文件大小；修改裁剪、时长或分辨率会立即更新估算。

视频大小主要由 **码率 × 时长** 决定，而不是仅由分辨率决定。旧版固定使用“最高画质”导出预设，重新编码的码率可能高于原文件，所以裁剪后仍可能变大。现在按画质档位明确设置目标码率，并参考来源码率约束预算。预估包含音频和少量容器开销；实际大小会随画面复杂度、可变码率和短视频开销变化，不是文件大小保证。压缩是有损的，多次压缩不能恢复细节。

## 权限与边界

- 屏幕录制及音频权限由 macOS 管理；拒绝授权后可在“系统设置 → 隐私与安全性”中修改。
- 单独录制标签页时，请先把该标签页移到独立浏览器窗口。录制的是窗口，可在编辑时裁掉边框。
- 来源音频由系统按共享范围提供，受保护内容可能无法捕获。程序排除自身播放的声音，避免编辑器音频被录入。
- 第一版不提供暂停、多轨时间线、转场、字幕、滤镜、HDR、自动更新或商店发布。
- 捕获帧率目标为 30 fps；静态画面、系统负载及硬件编码能力可能影响实际采样。

## 工程与测试

- `Sources/RecorderCore/`：裁剪与时间校验、状态、分辨率和文件命名。
- `Sources/ScreenRecorder/`：桌面界面、系统捕获、预览、编辑与导出。
- `Tests/`：XCTest 单元测试与真实媒体导出测试。
- `Config/`：应用元数据与音频输入 entitlement。

```sh
./scripts/test.sh                           # 所有 XCTest 测试
./scripts/test.sh --filter RecordingModelsTests
./scripts/test.sh --filter LocalizationTests
python3 scripts/generate-project.py          # 增删 Swift 源文件后更新 Xcode 工程
./scripts/ci.sh                              # 要求媒体工具齐全，禁止跳过测试
```

Xcode 工程与 Swift Package 共用源文件；测试通过 Swift Package 执行。脚本将构建及模块缓存保存在项目内。媒体测试使用本地 FFmpeg 软件编码，实际验证裁剪、旋转、压缩和格式组合；未安装工具时会明确标记跳过。

可选的 `./scripts/create-fixture.sh` 生成含双音轨的测试素材。验收场景及本次验证记录见 [docs/VALIDATION.md](docs/VALIDATION.md)。

### GitHub Actions 与版本维护

[CI](https://github.com/doskey75506/ScreenRecorder/actions/workflows/ci.yml) 在每次推送、PR 和手动触发时运行。Intel 和 Apple Silicon 两种 macOS runner 均执行完整 XCTest、检查生成的 Xcode 工程、构建双架构 Release 应用，并验证签名与架构。CI 要求 FFmpeg 软件编码器齐全，任何测试跳过均视为失败。

每个任务保留测试报告、构建日志和应用 ZIP，保存 14 天。CI 应用为开发版本，未公证；使用编辑功能仍需另行安装 FFmpeg。录屏授权、实际屏幕 / 麦克风捕获、长时间录制及主观画质仍需实机验收。

每次代码更新都应维护 GitHub 提交、检查 CI，并同步中英文 README 和 [CHANGELOG.md](CHANGELOG.md)。具体提交和发布约定见 [CONTRIBUTING.md](CONTRIBUTING.md)。
